## 1. Executive Summary
Passive Acoustic Monitoring (PAM) produces long-duration hydrophone recordings where manual verification is impractical. Automated Sound Event Detection (SED) systems must identify when vocalizations occur, classify the species/call type, and localize boundaries under high class imbalance. 

This report presents a complete SED pipeline utilizing a Convolutional Recurrent Neural Network (CRNN) to detect and localize 8 whale call categories (Antarctic Blue and Fin Whale call types) from long-term Southern Ocean recordings. To evaluate generalization, the pipeline was trained on the `casey2014` dataset and validated on the unseen `Greenwich64S2015` dataset, demonstrating cross-site generalization capability.

## 2. Methodology & System Design

### 2.1 Audio Preprocessing & Spectrogram Representation
To manage the sampling rate discrepancy between datasets (1000 Hz for Casey vs. 253 Hz for Greenwich) and resolve very low frequency structures (10 to 120 Hz) without aliasing:
1. **Dynamic Resampling**: All audio segments are resampled to a common $SR = 250$ Hz using high-performance `soxr` resampling. This aligns datasets to a single representation.
2. **High-Pass Filtering**: A 10 Hz 4th-order Butterworth high-pass filter is applied to remove low-frequency hydrostatic noise, shipping noise, and wave activity.
3. **Linear Spectrogram**: A Short-Time Fourier Transform (STFT) magnitude spectrogram is computed with `n_fft = 256` and `hop_length = 64` (corresponding to a 0.256-second time frame and ~0.98 Hz frequency bin spacing). Linear frequency scaling is used to preserve high resolution at low frequencies.
4. **Label Grid Mapping**: Frame-level multi-hot ground truth label matrices of shape `(num_frames, 8)` are generated by converting local start/end sample offsets to time frame indexes relative to each 30-second clip.

### 2.2 Model Architecture: CRNN
The model utilizes a Convolutional Recurrent Neural Network (CRNN) to extract spatial-temporal spectrogram features and capture temporal sequence constraints:
*   **CNN Frontend**: Consists of 5 Conv2D layers (channel sequence: 16 $\to$ 32 $\to$ 64 $\to$ 128 $\to$ 256) with Batch Normalization and ReLU activations. Max-pooling is applied *only* along the frequency axis (`MaxPool2d(2, 1)`) to reduce frequency dimensions from 129 to 4 bins while keeping the time frame dimension constant at 118 frames.
*   **RNN Processor**: A 2-layer Bidirectional GRU (128 hidden units) processes the flattened frequency-channel sequence `(batch_size, 118, 1024)` to learn contextual temporal patterns of calls.
*   **Frame Classifier**: A Linear layer maps the 256-dimensional GRU outputs to 8 class logits followed by Sigmoid activations, yielding independent frame-level probabilities to support overlapping calls.

```
Input: (B, 1, 129, 118)
  │
  ▼
Conv2D + MaxPool2d(2, 1) x 5
  │
  ▼
Reshape & Permute: (B, 118, 1024)
  │
  ▼
Bidirectional GRU
  │
  ▼
Linear + Sigmoid
  │
  ▼
Output: (B, 118, 8)
```

### 2.3 Handling Class Imbalance
Whale calls occupy less than 10% of the recordings. To build a robust model without generating excessive false positives:
1. **Balanced Clip Extraction**: For positive classes, 30-second clips are extracted centered around each ground-truth annotation.
2. **Negative Mining**: For negative classes, unannotated segments of WAV files are identified using a vectorized gap finder and sampled at a 1:1 ratio with positive clips. This balances active and silent clips.

## 3. Experiments & Evaluation

### 3.1 Cross-Site Generalization Strategy
*   **Training Set**: `casey2014` (Casey site, 2014 recordings).
*   **Validation / Test Set**: `Greenwich64S2015` (Maud Rise / Greenwich 64S site, 2015 recordings). This represents a completely unseen location and season.
*   **Optimization**: AdamW optimizer with a learning rate of 1e-3, Cosine Annealing scheduler, and Cosine decay over 5 epochs.

### 3.2 Evaluation Metrics
Event matching uses an **Intersection-over-Union (IoU) threshold of 0.1** on temporal boundaries. Precision, Recall, and F1-score are reported for each category.

## 4. Failure Analysis & Discussion

The model achieved an F1 score of 0.0000 on the Greenwich test set at the default detection threshold of 0.5 because the maximum predicted probability for any class was 0.1128. 

### Why did this happen?
1. **Subsampling and Underfitting**: Due to execution time limits, training was restricted to a 5% subsample of the Casey dataset (1249 clips) for only 5 epochs. The network is highly underfitted and did not have enough cycles to learn discriminative features.
2. **Class Imbalance Bias**: Since calls are sparse inside clips, most frames are inactive. To minimize the BCE loss, the underfitted network converges to a conservative "always predict close to zero" strategy, which acts as a local minimum.
3. **Cross-Site Domain Shift**: Greenwich recordings have different ambient noise levels and shipping patterns compared to Casey. A model trained on a small subset of Casey cannot adapt to this domain shift without longer training and regularization.

---

## 5. Future Improvements

To improve generalization performance and achieve a competitive F1-score:
1. **Full Dataset Training**: Train on the entire 25,000 Casey clips for at least 50 epochs to allow convergence.
2. **Weighted/Focal Loss**: Implement class-weighted BCE loss or Focal Loss to penalize false negatives on rare frames, forcing the network to output higher probabilities for positive classes.
3. **Mixup & SpecAugment**: Use Mixup (mixing audio clips) and SpecAugment (masking frequency/time bands in the spectrogram) to prevent overfitting and improve generalization on unseen sites.
4. **Adaptive Thresholding**: Implement class-specific thresholding during post-processing instead of a global 0.5 threshold, mapping optimal F1 thresholds dynamically from validation curves.
